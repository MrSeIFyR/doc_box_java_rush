# DocBox — Система хранения и управления документами
<a id="top"></a>

**DocBox** — это веб-приложение для загрузки, просмотра, поиска и удаления документов (PDF, TXT, MD, DOCX) с хранением метаданных в базе данных PostgreSQL. Проект полностью контейнеризирован и управляется через Docker Compose.

## 🚀 Быстрый старт

### Требования
- Docker и Docker Compose
- PowerShell или терминал (для запуска скриптов)

### Запуск проекта

Из корневой папки проекта выполните:

```powershell
docker compose up --build
```

После успешной сборки контейнеры app и db перейдут в статус Up, а приложение станет доступно по адресу: http://localhost:8000/

⚠️ При первом запуске база данных инициализируется автоматически (скрипт init.sql создаст таблицу documents).

## 💾 Резервное копирование БД
Все операции бэкапа логируются в logs/app.log.

Бэкап делается утилитой `pg_dump` внутри контейнера PostgreSQL, результат сохраняется на хосте в папке `backups`.

### Подготовка
1. Папка `backups/` создана в корне проекта.
2. В `.gitignore` добавлена строка `backups/`.
3. В `compose.yaml` у сервиса `db` добавлен volume: `- ./backups:/backups`.
4. Проект запущен: `docker compose up --build`.

### Создание бэкапа вручную
Из корня проекта:

```powershell
.\backup.ps1
или 
python backup_db.py
```
Результат: файл вида backups/backup_2026-10-18_153412.sql

### Восстановление из бэкапа
Пример восстановления (подставь актуальный ID контейнера или используй автоопределение):

```powershell
$cid = docker compose ps -q db
$file = ".\backups\backup_2026-10-18_153412.sql"
$env:PGPASSWORD = "password"
Get-Content $file | docker exec -i $cid psql -U postgres -d docbox_db
Remove-Item Env:\PGPASSWORD
```
После восстановления перезапускать контейнеры не требуется.

## 📝 Логирование

Все действия приложения и скрипта бэкапа пишутся в файл logs/app.log.

#### Что логируется:

* Успешная загрузка файла (оригинальное имя, размер, новое имя).
* Попытка скачивания файла.
* Удаление документа (включая случаи, когда файл отсутствует на диске).
* Ошибки с полным стеком вызовов (traceback).
* Процесс бэкапа (старт, найденный контейнер, успех/ошибка).

#### Формат записи:
```
2026-10-19 18:45:12 INFO: Файл успешно загружен: отчёт.pdf (123456 байт), сохранён как a1b2c3d4... [in /app/app.py:45]
2026-10-19 18:46:05 ERROR: Ошибка при удалении документа ID=5: [Errno 2] No such file or directory [in /app/app.py:98]
```

####  Просмотр последних записей:
```
Get-Content .\logs\app.log -Tail 20
```
Логи используют ротацию: максимальный размер файла — 5 МБ, хранится до 3 копий истории.

## 🛠 Разработка и сборка
### Пересборка образа
#### Если вы изменили Dockerfile или requirements.txt:
```
docker compose down
docker compose up --build
```

### Проверка метаданных в БД
#### Таблица documents содержит следующие поля:
* id: SERIAL PRIMARY KEY
* stored_name: уникальное имя файла на диске (UUID)
* original_name: оригинальное имя, загруженное пользователем
* size_bytes: размер файла в байтах
* upload_at: дата и время загрузки (автоматически)
* extension: расширение файла

#### Проверить содержимое можно через консоль контейнера:
```
$dbContainer = docker compose ps -q db
docker exec -it $dbContainer psql -U postgres docbox_db -c "SELECT * FROM documents;"
```

## 🔐 Безопасность и переменные окружения
* #### Пароль базы данных (POSTGRES_PASSWORD) задан в compose.yaml для локальной разработки.
* #### Скрипт бэкапа (backup_db.py) использует жестко заданный пароль для удобства локального тестирования. Для продакшена пароль следует вынести в переменные окружения и передавать через os.getenv().
* #### Папки uploads, logs, backups проброшены через Docker volumes, чтобы данные сохранялись на хосте даже после удаления контейнеров.

## ❓ Частые проблемы и решения

| Проблема                          | 	Решение                                                                                                                    |
|-----------------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| Permission denied при git push    | Проверьте, под каким аккаунтом авторизованы в Git. Убедитесь, что у вашего пользователя есть права на запись в репозиторий. |
| Контейнер db не может запуститься | Проверьте, не занят ли порт 5534 другим процессом.                                                                          |
| Ошибка аутентификации при бэкапе  | Убедитесь, что пароль в backup_db.py совпадает с POSTGRES_PASSWORD в compose.yaml.                                          |
| Файлы не сохраняются в uploads    | Проверьте наличие volume - ./uploads:/app/uploads в compose.yaml и права на запись в папку на хосте.                        |
